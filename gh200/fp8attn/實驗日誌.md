## 2026-10-05：量測我們實際設定下 FP8 attention backward 的 stale-delta 殘差（Delta-Matching 論文）

### 問題

Delta-Matching（arXiv 2609.37852）指出：FlashAttention backward 用 δᵢ = ⟨dOᵢ, Oᵢ⟩，
FP8 下 O 與 dO 各自量化後，dS = P∘(dP − δ) 的列和不再為 0。論文量到的正規化列和殘差是
1e-2–5e-2，而且有方向性偏差。論文建議的修法是 δᵢ = Σⱼ Pᵢⱼ·dP̂ᵢⱼ。

我們的 MLPerf Llama2-70B LoRA 提交設定（TE 2.2、`FP8_DPA=1`、`NVTE_FP8_DPA_BWD=1`）用的正是
cuDNN FP8 attention 的 forward 和 backward。這一節要回答兩件事：我們有沒有這個偏差？量級多大？

### 結論

1. **有 stale-delta 殘差，但沒有方向性偏差。**
   - 我們的 cuDNN FP8 backward 用 stale δ（已數值確認），正規化列和殘差平均約 1.7e-2，
     落在論文的 1e-2–5e-2 區間的低端。
   - 但殘差的有號平均只有平均絕對值的 ≤2%，正負比例約 50/50，而且正負號隨層與 step 改變。
     dq 在 K̄ 方向的有號分量 ≤0.5% RMS。
   - 在我們的資料上，它表現為零均值雜訊，**看不到論文所說的系統性偏差**。
2. **stale 項不是 FP8 attention backward 的主要誤差。**
   - stale 項約占 ‖dq‖ 的 5%。總 dq 誤差約 12%，主要來自 dS 和 dO 的 E5M2 量化，以及 delayed
     scaling 的飽和。
   - 套用 Delta-Matching 只把 dq 誤差從 11.7% 降到 11.2%（中位數）。
   - E5M2 量化 dS 本身就會帶回同量級、但無偏的列和雜訊。
3. **對 280 步 LoRA finetune 的意義：影響可忽略。**
   - LoRA 的 linear_qkv 梯度是 dq·xᵀ 對每步 8192×GBS 個 token 求和，零均值的 per-token 雜訊會被平均掉，
     遠小於 minibatch 抽樣雜訊。
   - 論文說的退化需要長時間累積的同號偏差（pretraining），我們量不到這種偏差，而且 run 很短。
   - 這和實測一致：FP8 attention 的收斂點平均 3842 samples，BF16 RCP 是 3819，兩者沒有差別。
4. **真正值得注意的是 delayed scaling。**
   - 冷啟動：step 1、2 的 attention 梯度是 0，step 3 嚴重飽和。
   - amax_history=4 時偶發的 dQKV、dS 飽和（例如 L0 s30）。
   - 這只影響約 3/280 步加上偶發事件，沒有改變收斂，但它比 stale delta 大一個量級。
   - 如果要換 kernel，例如自己寫 FP8 attention，各方案的收益如下：
     - per-tensor current scaling：主要消除冷啟動和飽和事件（step 3 的 dq 從 19–57% 降到 7–16%），
       穩態中位數只從 11.7% 降到 11.4%。
     - block-scaled E4M3：穩態 dq 中位數 11.7% → 8.0%。
     - Delta-Matching：11.7% → 11.2%。
   - 兩者的收益都大於 Delta-Matching，而且三者可以並用。

## 自寫 FP8 attention — 階段 1：Triton 原型（fwd + Delta-Matching bwd）

### 設計（`fp8attn.py` = v1 指標載入版；`fp8attn2.py` = v2 TMA 版，之後的數字都是 v2）

- **量化**：Q/K/V/dO 都是 E4M3，每個 (head, 128 列) 區塊一個 fp32 dequant scale（amax/448），由量化 kernel
  即時算（current scaling，不用 TE 的 delayed-scaling 歷史）。Hopper FP8 wgmma 要求兩個運算元都是 K-major，
  所以量化 kernel 同時寫出轉置副本（V^T 給 fwd 的 PV；Q^T、K^T、dO^T 給 bwd 的 dK/dV/dQ）。
- **P** 以固定 scale 256 量化（P≤1），並把 V/K/dO 的區塊 scale 折進 P 的係數，讓累加器不必每次迭代重新縮放。
- **forward**：Q-outer online softmax，存 lse 與列最大值 m（bwd 要用）。
- **backward = 量化 kernel + dq kernel（Q-outer）+ dkdv kernel（KV-outer，在 kernel 內迴圈跑共用同一個 KV head 的
  8 個 query head，dK/dV 留在暫存器，不用 atomics）**。
- **Delta-Matching 的排程問題**：δᵢ = Σⱼ Pᵢⱼ·dP̂ᵢⱼ 要整列跑完才知道，但 dS 需要 δ。做法是在 Q-outer 的 dq kernel 裡
  邊掃 KV 邊累加 δᵢ，並用線性展開在同一趟算完 dQ：
  `dQᵢ = Σⱼ Pᵢⱼ(dP̂ᵢⱼ − δ⁰ᵢ)kⱼ − (δᵢ − δ⁰ᵢ)·Σⱼ Pᵢⱼkⱼ`，δ⁰ = ⟨dO,O⟩（stale δ）只當置中常數，讓第一項的
  FP8 量化尺度正確（直接用 δ⁰=0 會有抵消誤差）。代價是多一個 FP8 GEMM（P·K）。dkdv kernel 接著直接用匹配後的 δ。
  總共 8 個 FP8 GEMM（dq 4 + dkdv 4），對照 FA3 BF16 的 5 個 BF16 GEMM；兩個 kernel 各算一次 exp。
  `matched=False` 是 stale-δ 對照組（δ=δ⁰、不做 P·K）。
- **dS 量化**（`DS_SCALE`）：0 = 每個 tile 每列 amax（準，但累加器每次迭代要多一個 FMA）；
  2 = 每列固定 scale，用 Cauchy-Schwarz 上界 Pmax·(|dOᵢ||v|max+|δ⁰ᵢ|)×1.25，並把 scale 折進 exp2 的偏移（最快）；
  3 = 樂觀起始 + 溢位時 2 的冪次下修（太慢，放棄）。
- dkdv kernel 用 P' = exp2(s − mᵢ)（每列最大值恰為 1）取代正規化的 P，1/lᵢ 折進 Q^T、dO^T 的量化副本；
  否則平坦注意力的列（P ~ 1/8192）在 E4M3 會掉進 subnormal（L00 的 dV 誤差 0.126 → 0.053，job 3273）。

最佳設定：fwd BM128/BN64/4 warps/3 stages；dq BM64/BN64/4 warps/3 stages（248 regs，每 SM 2 個 CTA）；
dkdv BM64/BN128/8 warps/3 stages（254 regs，每 SM 1 個 CTA）。

- Triton 3.8 的 `warp_specialize` 在 Hopper 4 warps 時編譯失敗（PassManager::run failed），8 warps 時無效果。
- Nsight Compute 不能用（ERR_NVGPUCTRPERM），改看 SASS（job 3268，`inspect_asm.py`）：迴圈是 QGMMA → 等待 →
  MUFU.EX2（每個 warp 指令佔 8 cycle）→ FMUL/FFMA → F2FP → 下一個 QGMMA，**tensor core 與 exp/FP32 幾乎沒有在同一個
  CTA 內重疊**，只靠每 SM 2 個 CTA 互相掩蓋。dq kernel 每個 64×64 tile 約 1330 cycle，而 4 個 FP8 GEMM 的 tensor
  下限是 512 cycle；dkdv 約 2060 cycle。FA3 BF16 bwd 每 tile 約 2044 cycle（5 個 BF16 GEMM 下限 1280）。
- 結論：FP8 backward 在 Hopper 上是 **ALU/MUFU 受限** 不是 tensor 受限：每個 S 元素要 2 次 exp（兩個 kernel 各一次）
  + 約 6–8 個 FP32 運算 + 2 次 FP8 轉換，Triton 又沒辦法做 FA3 那種 warpgroup ping-pong / 生產者-消費者重疊。
  cuDNN 自己的 FP8 bwd（8.4 ms）比它的 BF16 bwd（5.2 ms）慢 1.6 倍，也是同一個現象。

### CUDA/CuTe（CUTLASS 3.x）路線評估（未動工）

- 上界估計：每個 64×64 tile 8 個 FP8 GEMM = 1024 tensor cycle；兩趟 exp 的 MUFU 共 512 cycle、FMA 管線約 400 cycle。
  完美重疊約 1100 cycle/tile，是 FA3 BF16 實測（2044）的 1.9 倍快；以 FA3 自身約 63% 的效率估，實際約
  1600–1750 cycle → bwd 約 3.3–3.6 ms（含量化），比 FA3 BF16 快約 20–25%，每層省約 1 ms、每步約 80 ms（~3%）。
- 工作量：以 FA3 `hopper/` 的 sm90 bwd 為底，(1) 全部運算元改 FP8 並用 TMA 載入預先轉置的 K-major 副本
  （Qᵀ、Kᵀ、dOᵀ，量化 kernel 已經有了），smem 預算要重排；(2) P、dS 從累加器轉成 FP8 RS-wgmma 運算元的 byte
  permute（FA3 FP8 fwd 有現成寫法）；(3) Delta-Matching：最省事的是加一個輕量 δ pre-pass kernel（QKᵀ、dOVᵀ 兩個
  FP8 GEMM + exp + 列和），主 kernel 沿用 FA3 的 dQ fp32 TMA reduce-add。估計熟手 2–4 週，風險高
  （NVIDIA 自己的 cuDNN FP8 bwd 都比 bf16 慢）。
- 相較之下，直接採用 FA3 BF16（fwd+bwd）就能拿到相對現況每層 −3.8 ms（約 −0.31 s/步，隔離量測估計），
  而且數值是 BF16。自寫 FP8 bwd 最多再多 ~3%。**建議不投入 CUTLASS 大工程**。

## 10-06 09:45 FP8 delayed scaling 冷啟動修正（`reset_fp8_stats`）— 調查與實驗開始

### reset 在哪裡、為什麼

### 規則（`mlcommons/training_policies` master `training_rules.adoc` 原文）
- 「The clock must start before any part of the system touches the dataset or when the maximum model initialization time is exceeded.」
- 「Prior to starting the clock, a system may use a maximum model initialization time of 30 minutes for _Closed_ division …
  Model initialization time begins when the system first begins to construct or execute the model.」
- Pre-training is not allowed：「the implementation should not encode any information about the content of the dataset or a
  successful model's state in any form. High-level statistical information about the dataset, such as distribution of sizes, may be used.」
- CLOSED：「Weights and biases must be initialized using the same constant or random value distribution as the reference
  implementation, unless a pre-trained set of weights, such as a checkpoint or backbone, is used by the reference.」
- 判斷：FP8 scale/amax 不是權重，也不在超參數表；warmup 的 amax 來自合成資料加上官方 checkpoint，沒有碰資料集，也不含「successful

### 做法選擇（575 W、約 1260 MHz 下的下限估計）

每個 FP8 GEMM（causal、64 heads、S=8192、d=128）0.55 TFLOP；1260 MHz 時 FP8 tensor 峰值約 1.36 PFLOP/s → 每個 GEMM 0.40 ms；
每趟 exp（2.1G 個元素）MUFU 下限約 0.8 ms。

| 做法 | FP8 GEMM | exp 趟數 | tensor 下限 | 其他 |
|---|---|---|---|---|
| (1) Q-outer dq（含 accB=ΣPK 與 δ）＋ KV-outer dkdv | 8 | 2 | 3.2 ms | 精確；不需 smem 轉置、不需 atomics |
| (2) δ pre-pass ＋ FA3 式單一 KV-outer kernel（dQ atomics） | 7 | 2 | 2.8 ms | 精確；dS 要在 smem 做 FP8 位元組轉置寫入 |
| (3) forward 多算 O′=P·V̂，bwd 標準 5 GEMM | 5（+fwd 1） | 1 | 2.0 ms（+0.4） | 近似（bf16 級殘差）；要改 forward；同樣要 dS 轉置 |

選 (1)：唯一不需要 FP8 dS 轉置寫入 smem 與 dQ atomics 的版本，P、dS 直接從累加器暫存器當 RS-wgmma 的 A 運算元，
最容易先驗證正確；Triton 版已證明數學。(2)(3) 的 tensor 下限較低，但工作量大得多（FA3 FP8 forward 的 V 轉置那種
LDSM.T＋byte permute＋STSM，以及 fp32 dQ reduce-add）。

### 實作重點

- 量化 kernel：Q、K、V、dO 每 (head, 128 列) 一個 scale；K^T、Q'^T、dO'^T（Q'、dO' = 列乘 Pmax）的轉置副本，
  序列索引在每 16 個一組內按 `perm16` 重排，正好對上 `permute_Cregs_fp8` 之後累加器暫存器當 FP8 A 運算元時的 K 索引
  （不用 shuffle，A 運算元的轉換只是暫存器改名）。
- dq kernel（每 CTA 128 個 query 列、2 個 consumer warpgroup、1 個 TMA producer warp、4 stage）：S、dP（SS-wgmma）、
  P 與 dS 轉 FP8 後 accA += dS·K、accB += P·K（RS-wgmma）；δ = Σ P·dP（FP32）；dQ = accA − (δ−δ0)·accB；同時輸出 δ 與 Pmax。
  若有 forward 的列最大值（fp8attn2 的 mrow）就直接用，省掉 P 的 amax 追蹤。
- dkdv kernel（每 CTA 128 個 key、迴圈跑同一 KV head 的 8 個 query head，dK、dV 留在暫存器，無 atomics）。
- dS 的 FP8 scale：每列「延遲縮小」— 列的 running amax 剛好落在 448（非 2 的冪），超出時累加器那一列乘一次 f。
  比較過：用 2 的冪（落在 224–448）在真實 dump 上 dK 誤差差 5–10%（主導元素的捨入運氣），per-head 正規化要用
  per-(head,128 列) 的 Q'/dO' scale（per-head 單一 scale 在 L00 dV 變差 20%）。

### 原因（clock64 分段、SASS 與微基準）

- 每個 CTA 迭代（128×64 的 S tile）：tensor 只需 1024 cycle（4 個 FP8 GEMM），實測 dq 約 2550、dkdv 約 3000 cycle
  （per-iteration profile，`-DFP8DM_PROF`）。
- 拆開看（dkdv）：發出並等 S/dP GEMM 約 820、元素運算約 1550、發出並等 dK/dV GEMM 約 560 cycle；兩個 consumer warpgroup 鎖步，
  GEMM 與元素運算幾乎沒有重疊。強制 ping-pong（named barrier 輪流發 GEMM）、延遲第二個 WG 起跑都沒改善（±5%）。
- 元素運算本身就貴：微基準（`alu_bench.cu`）同樣的每元素指令組合（FFMA、ex2、FFMA、2×FMUL、FMNMX、F2FP）在每 SM 2 個
  warpgroup 時要 870 cycle／迭代，去掉 exp 仍 590 cycle — 是發射頻寬上限（每 SMSP 每 cycle 1 道指令），不是延遲。
  FP8 的 GEMM 時間只有 bf16 的一半，但每元素的工作（Delta-Matching 的 Σ、P 與 dS 兩次 FP8 轉換、lazy scale 的 amax）
  比 FA3 bf16 多一倍；兩個 kernel 各算一次 exp。
- 要重疊就得在暫存器裡同時放兩組 S/dP：dq 的 accA＋accB（128）＋S/dP（64）已近 240 上限，跨迭代軟體管線化會溢出
  （ptxas C7511/C7513：wgmma 被序列化、spill 1 KB），切半 tile 則讓 SS-wgmma 變成 N=32、受 smem 頻寬限制。
- 換算：若能把 GEMM 與元素運算完全重疊，每迭代約 max(1024, ~900) ≈ 1100–1300 cycle，bwd 在 1.26 GHz 約 5–6 ms，
  才有機會贏 cuDNN（7.3 ms）；但這需要 FA3 等級的 warpgroup 排程，並且很可能要改成做法 (2)/(3) 的單一 KV-outer kernel
  （只算一次 exp、5–7 個 GEMM），估計還要 1–2 週以上，結果仍只是持平到小贏。
- 同條件下 FA3 bf16 bwd（6.70 ms）已經比 cuDNN FP8 bwd（7.32 ms）快，而且數值是 bf16。
